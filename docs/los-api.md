# Контракт `tuloma.los` 0.1

Дата: 2026-11-08. Источник исходной статьи: `likern/tuloma`
`5e3f52ee6d5e8bdd6e8e1aeb9476ed847be73ce4`.

## Назначение и статус

Немедленные низкоуровневые операции над NumPy. Python остаётся glue code.
Вызов метода должен выполнять именно этот запрос и возвращаться в Python.
Планировщика, Engine/Query builder, скрытого batching и кеша здесь нет.

В данном PR реализована только инфраструктура. Каждый геометрический entrypoint
вызывает соответствующую Rust-функцию в `crates/tuloma-los/src/queries.rs`.
Пока она возвращает `Error::NotImplemented`, Python получает `NotImplementedError`
с именем операции и путём к файлу. Нет фиктивных нулей, пустых результатов,
`todo!()` panic или Python fallback. `ALGORITHMS_IMPLEMENTED` равен `False`.

Результирующие типы, упаковка собственных Vec в ndarray и обработка `out=`
уже подключены: реализация Rust-функции не требует переписывать Python facade.

## Модель

`x,z` задают график кусочно-линейной функции `g(x)`, грунт расположен ниже неё.
Неравномерные абсциссы допустимы. Узлов N>=2, звеньев N-1; все координаты
конечны, x строго возрастает. Единица обеих координат - метр.
Нависающие поверхности, NoData, геодезические CRS, frame/epoch transformations,
геоид, кривизна/рефракция здесь не моделируются. Неизвестные данные отклоняются.

Точки A/B передаются как `(x,z)` с абсолютными координатами в этой же плоской
системе. `point(x, agl=h)` предполагает вертикальную высоту `h>=0` над `g(x)`.
Запросы не экстраполируют рельеф за пределами `[x[0], x[-1]]`.

`P(t)=A+t(B-A)`, 0<=t<=1; порядок результатов по t всегда от A к B,
включая обратное горизонтальное направление. Препятствия за B не учитываются.
Вертикальный случай в `classify` резервирует статус `SameX`, как в статье.
Остальные операции, не определённые для вертикального или вырожденного сегмента,
должны явно вернуть ошибку, а не произвольный bool. Полную вертикальную геометрию
можно добавить отдельной ветвью при ручной реализации.

## Владение и поддерживаемое хранилище

- `Scene1D(x,z)` и `from_numpy(x,z)` сохраняют **те же** NumPy-объекты.
- Только exact `numpy.ndarray`, rank 1, native-endian float64, aligned и contiguous.
  Списки, MaskedArray/subclasses, float32, byte-swapped и strided/reversed входы
  отклоняются; автоматической конверсии/packing нет.
- Readonly входы допустимы; `out` должен быть writable, совместимой формы,
  без пересечения со всеми входами и хранилищем сцены.
- `x`/`z` getters возвращают исходные объекты, а не копии.
- Python-владельцы сохраняются через `Py<PyArray1<f64>>`. Rust slices/view живут
  только внутри метода, вместе с guards `rust-numpy`.
- Данные можно менять между вызовами. Каждый запрос заново проверяет конечность,
  размеры и монотонность: это O(N) проверка границы, отдельно от стоимости ядра.
  Ускорение с кешированием возможно позднее только с явным протоколом изменений.
- Нельзя конкурентно писать в любой alias или выполнять resize во время метода.
  GIL не является глобальной блокировкой стороннего native-кода. Detach/Rayon и
  free-threaded CPython в этот профиль поддержки не включены.
- Новый вычисленный результат требует нового буфера. `Vec.into_pyarray()`
  передаёт его NumPy без копии элементов. Буферы точек `Vec<[f64;2]>` превращаются
  в матрицу через `into_flattened()` и `from_shape_vec()`, затем передают владение.
  `out=` даёт отдельную точку реализации записи в готовый буфер.
- Rust-owned NumPy outputs могут иметь base-owner и не поддерживать realloc/resize.
  Скалярные координаты копируются как несколько чисел; zero-copy относится к массивам.

## Интерфейс

| Entry point | Контракт после ручной реализации |
| --- | --- |
| `Scene1D(x,z)`, `from_numpy(x,z)` | Заимствование и структурная валидация; уже работают |
| `from_uniform(z, x0=0, dx=1)` | Создание новой производной оси x, сохранение z; пока заглушка |
| `validate()`, `len(scene)`, `scene.x`, `scene.z` | Инфраструктура хранилища; уже работает |
| `height(xq, out=None)` | `g(xq)`, скаляр или float64[M] |
| `point(x, agl=0)` | `(x,g(x)+agl)` |
| `node_range(xa,xb, interior=True)` | `(start,stop)` для slice x[start:stop], строго внутренние узлы по умолчанию; x остаётся возрастающим |
| `locate(P, atol=0)` | `Location.Above`, `On`, `Below` |
| `visible(A,B,touch='allow',atol=0)` | Видимость внутренности AB; контакты только в A/B не блокируют |
| `classify(A,B,atol=0)` | `Visibility.Visible`, `Touch`, `Blocked`, `SameX` |
| `clearance_at(A,B,xq,out=None)` | `c(x)=z_AB(x)-g(x)` в заданных позициях между A/B |
| `clearance_profile(A,B)` | Параметры и зазоры на обрезанных границах и исходных узлах |
| `clearance_extrema(A,B)` | Экстремумы на замкнутом AB; при равенстве выбирается первый по t |
| `intersections(A,B,endpoints=False)` | Изолированные контакты + интервалы совпадений |
| `below_intervals(A,B)` | float64[M,2], границы компонент c(t)<0 в параметре t |
| `first_intersection(A,B,endpoints=False)` | Первый достигнутый контакт по t или None |
| `lerp(left,right,t,out=None)` | Скалярная/векторная интерполяция |
| `segment_points(A,B,t,out=None)` | Одна точка или float64[M,2] |
| `line_height(A,B,xq,out=None)` | Высота невертикальной прямой AB; для вертикального случая ошибка |

Сигнатуры Python зафиксированы в `packages/tuloma/python/tuloma/los/__init__.pyi`.
Векторные аргументы xq/t - rank 1, float64. Для segment_points out имеет
C-layout и форму `(len(t),2)`; остальные векторные out - `(len(input),)`.
Скалярные входы возвращают Python float/tuple и не принимают out.
Скалярные left/right в lerp не broadcast-массивы в этой версии.

## Значение результатов

`ClearanceExtrema`: min_value, max_value, min_point, max_point,
min_parameter, max_parameter. Зазор вертикальный и знаковый, не кратчайшее
евклидово расстояние до ломаной. Максимальная глубина: `max(0,-min_value)`.
`min_point` и `max_point` лежат на луче: это P(t) при соответствующем экстремуме.
Если концы на земле, минимум на закрытом отрезке может равняться нулю только
из-за концов. Минимум на открытом интервале может вообще не достигаться.

`ClearanceProfile`: parameters[M], clearance[M], float64; 0 и 1 и все
внутренние исходные узлы включены в порядке A->B. Это вычисленный результат,
а не произвольная равномерная аппроксимация профиля.

`Contacts`: points[K,2], parameters[K], kinds[K] uint8 (Enter=1, Exit=2,
Touch=3), overlaps[J,2] в t. Одна общая вершина двух звеньев не дублируется.
Enter/Exit ориентированы от A к B, Touch означает контакт без смены стороны.
Число общих точек при overlap бесконечно; len(points) считает только изолированные.
Если первый контакт не достигается из-за исключённого конца интервального
совпадения, first_intersection должен вернуть явную ошибку, а не выдумать точку.

below_intervals возвращает **границы** компонент строгого c<0. Корни на
границах не относятся к грунту. Компоненты не склеиваются через изолированный
нулевой контакт. При обрезании по t=0/1 принадлежность самого конца определяется
его зазором; массив границ не является отдельным кодированием открытости концов.

## Численная семантика и статья

Теория использует точные знаки; f64 даже с atol=0 не является точной арифметикой.
Допуск не равен точности DEM и не является доказанной границей roundoff.
`atol` измеряется в метрах, должен быть конечным и неотрицательным.
Для повторения статьи явно передавать atol=1e-9; исходный низкоуровневый default - 0.
При наличии проникновения глубже atol статус Blocked; полоса около нуля
может отображаться как Touch. Политику надо применять последовательно к
внутренним узлам/совпадениям; касание только A/B само по себе не создаёт Touch.

Нельзя подменить максимум `d_i=g(x_i)-z_AB(x_i)` **внутренних узлов** статьи
экстремумом по замкнутому отрезку. Для таблицы используйте node_range,
line_height, `d=zi-ray_z`, `np.maximum.accumulate(d)`.
Пустой внутренний диапазон имеет отдельную ветвь; обе нулевые AGL на одном
звене дают совпадение. Равномерные отсчёты статьи идут от A по горизонтали,
исключают концы и не заменяют проверку исходных узлов.

## Покрытие существующего журнала

| Что нужно отрисовать | Достаточные примитивы |
| --- | --- |
| A/B, профиль, изменение AGL | height, point, исходные массивы |
| Вердикт и касание | visible/classify |
| Максимум превышения внутреннего узла | node_range + line_height + NumPy argmax |
| Части луча под рельефом | below_intervals + segment_points |
| Таблица и график разностей | узловые slices, line_height, clearance_profile, NumPy accumulate |
| Выборка 25/20 м | NumPy arange + height + line_height |
| Интерполяция и иллюстрация доказательства | lerp, segment_points |

Сейчас статью обслуживает отдельный неизменённый NumPy-референс.
Слой совместимости для прежних profile_los/compare_profile_los можно написать
после реализации Rust-примитивов. В scaffold его нет, чтобы заглушки нельзя
было перепутать с успешно работающим native-движком.

## Проверки при последующей реализации

Добавлять независимые геометрические тесты к каждому реализованному примитиву:
узлы/межузловые точки, B между отсчётами, A/B reverse, касание вершины,
совпадение со звеном, пустой диапазон, одинаковые x, вырожденный отрезок,
подземные точки, границы домена, невалидные численные параметры и близкие корни.
Для статьи контрольные корни: 106/3 и 298/7, превышение 6 м при x=40;
подъём B на 12 м даёт касание, на 16 м - видимость.
Тесты scaffold сейчас проверяют только интерфейс, память, ошибки и отсутствие
алгоритмической реализации. Тесты эталонной геометрии остаются отдельными.

При реализации очередного примитива заменяйте соответствующее ожидание
NotImplementedError в `packages/tuloma/tests/test_contract.py` геометрическими
проверками. Проверки владения и раскладки буферов сохраняются. `tests/browser/smoke.py`
также явно проверяет заглушки: обновляйте его по мере реализации выбранных методов.
